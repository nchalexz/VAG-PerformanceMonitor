# Промт для DashGrid: VPM как предустановленный элемент

Скопировать содержимое ниже в новую сессию агента в репозитории DashGrid.
Промт самодостаточен: он описывает контекст, решение, ограничения и критерии
приёмки. VPM в этой сессии не менять.

---

## Задача

Добавить **VAG Performance Monitor (VPM)** в DashGrid как предустановленный
элемент рабочего стола, связанный с VPM, не дублируя телеметрию и не открывая
второе соединение с ELM327.

Работать только в репозитории DashGrid. Репозиторий VPM и его APK не менять.

## Контекст

- VPM 0.4.0: `io.github.nchalexz.aaperfmon`.
  Репозиторий: https://github.com/nchalexz/AAPerformanceMonitor
  Тег: `v0.4.0`.
- В VPM два полноэкранных режима: главный экран (три аналогово-цифровых
  прибора и пять плиток) и расширенный (те же приборы, категории и адаптивная
  сетка). Оба реализованы в `io.github.nchalexz.aaperfmon.cockpit.CockpitActivity`.
- VPM владеет единственным соединением ELM327 и VAG UDS. У него есть
  `TelemetryService`, `TelemetryWidgetProvider` (стандартный AppWidget) и
  `CockpitActivity`.
- AA-сборка VPM остаётся шаблонным списком `ListTemplate`. Это не задача
  DashGrid; не пытайся перенести макеты в AA.
- DashGrid уже умеет:
  - `WorkspaceItemKind.PANE` — UI чужого приложения в ячейке;
  - `WorkspaceItemKind.APP` — ярлык приложения;
  - `WorkspaceItemKind.WIDGET` — встроенные карточки DashGrid;
  - `WorkspaceItemKind.ANDROID_WIDGET` — стандартный AppWidget через
    `AppWidgetHost`, `widgets/AndroidWidgets`, `ui/car/AndroidWidgetCell`;
  - запуск внешних Activity на VirtualDisplay через
    `launch/LaunchHostService`;
  - предустановленные/мигрируемые рабочие столы в `workspace/WorkspaceModel`.

## Решение, которое нужно реализовать

Основной путь — **app-pane**, а не нативный виджет:

1. Создать предустановленный рабочий стол **«Автомобиль»** (Car), 100 %,
   с одним элементом `WorkspaceItemKind.PANE` для VPM.
2. В панели открывать `CockpitActivity` VPM. Пользователь видит оба экрана
   VPM, свайпает их, открывает категории — без второго UI и без второго
   OBD-соединения.
3. VPM остаётся единственным владельцем ELM327. Для этой панели не запускать
   `obdapp` DashGrid, не подписываться на его PID и не открывать собственный
   OBD-поток.
4. Предустановка идемпотентна: добавить рабочий стол только если его ещё нет;
   не перезаписывать пользовательские рабочие столы, элементы и настройки.
5. Если VPM не установлен — показать в ячейке спокойную заглушку
   «VPM не установлен» с действием «Установить/Открыть». Не падать и не
   создавать пустую панель.

Компактный AppWidget — допустимый второй шаг, но **не вместо** app-pane:

- Использовать существующий `ANDROID_WIDGET` и `TelemetryWidgetProvider` VPM.
- Учесть: стандартный AppWidget нельзя «предустановить» без согласия
  пользователя. Нужен явный provisioning-экран (`allocateAppWidgetId` →
  `ACTION_APPWIDGET_BIND` → `bindAppWidgetIdIfAllowed`), а не тихая привязка.
- Это компактная карточка, а не два макета.

## Обязательная проверка перед кодом

Прочитай исходники DashGrid и ответь себе на вопросы:

1. Как `LaunchHostService` запускает чужую Activity на VirtualDisplay —
   хватает ли прав AARE, если Activity не экспортирована?
2. `CockpitActivity` VPM сейчас `android:exported="false"`. Может ли DashGrid
   запустить её напрямую? Если нет — не меняй VPM в этом репозитории.
   Зафиксируй точное требование к VPM и остановись с отчётом.
3. Видит ли AARE пакет VPM в каталоге приложений; нужен ли `<queries>`
   для `io.github.nchalexz.aaperfmon` в manifest DashGrid.
4. Как в `WorkspaceModel` устроены версия конфигурации, миграции,
   `defaultWorkspace()` и дефолтные элементы; где безопасно добавить
   предустановленный рабочий стол.
5. Как `WorkspaceHome`/`CarRuntime` создают, показывают и уничтожают pane;
   что происходит при сворачивании, переключении рабочего стола и выходе.

Если запуск `CockpitActivity` невозможен без изменения VPM — это нормальный
результат анализа. Предложи минимальное изменение VPM отдельным пунктом,
но не вноси его здесь.

## Ожидаемая реализация

- Детерминированный id предустановленного рабочего стола, например
  `workspace-aapm` или `car`; id не должен меняться между запусками.
- Миграция конфигурации: старые пользовательские конфигурации загружаются без
  потери; новый рабочий стол добавляется один раз.
- Подпись и иконка элемента — человеческие, не package name.
- `<queries>` для VPM, если требуется видимость пакета.
- Если AARE запускает только launcher-activity, рассмотреть запуск
  `MainActivity` VPM с extra, но только если VPM уже это поддерживает.
  Не добавлять хаки в чужое приложение.
- Не ломать существующий `obd`-виджет DashGrid и его настройки: это отдельный
  продукт, он остаётся доступным.

## Тесты и проверка

- Unit-тест: предустановка добавляет рабочий стол ровно один раз.
- Unit-тест: загрузка старой конфигурации не теряет элементы и не дублирует
  новый рабочий стол.
- Unit-тест: отсутствие VPM даёт заглушку, а не исключение.
- Проверка на эмуляторе/устройстве:
  - панель VPM открывается на весь экран;
  - оба экрана VPM листаются, категории работают;
  - back/сворачивание/возврат не ломают pane;
  - в логах нет второго соединения ELM327;
  - переключение рабочих столов не убивает телеметрию без необходимости.
- Сборка DashGrid, существующие тесты, скриншоты целевого разрешения
  (1920×720 и 1280×480, если поддерживается).
- Документация: что добавлено, как работает предустановка, что не проверено.

## Что не делать

- Не портировать UI VPM в DashGrid и не дублировать `CircularGauge`/`MetricTile`.
- Не добавлять второй IPC-канал телеметрии в первой итерации.
- Не менять AA-сборку VPM и не пытаться протащить Canvas в штатный AA.
- Не удалять и не переписывать существующий OBD-приложение/виджет DashGrid.
- Не делать виджет, который выглядит как VPM, но читает данные из OBD-стека
  DashGrid: это два разных владельца адаптера.

## Критерии приёмки

1. На чистой установке DashGrid есть рабочий стол «Автомобиль» с VPM.
2. VPM открывается как pane и показывает оба экрана; ввод и свайпы работают.
3. VPM — единственный владелец ELM327; второго соединения нет.
4. Повторный запуск не создаёт дубликаты и не затирает пользовательские данные.
5. Отсутствие VPM обрабатывается заглушкой.
6. Сборка и тесты зелёные; ограничения записаны честно.

## Если нужен мост в VPM

Не реализуй его здесь. В отчёте укажи минимум:

- экспортированный вход в cockpit (например, отдельная Activity-alias или
  `CockpitActivity` с `exported=true` и intent-filter
  `io.github.nchalexz.aaperfmon.action.COCKPIT`);
- либо extra в `MainActivity`, если это уже поддержано;
- влияние на безопасность: телеметрия только читается, запись в блоки
  недоступна, но экспортированный экран должен быть явно описан в VPM.
