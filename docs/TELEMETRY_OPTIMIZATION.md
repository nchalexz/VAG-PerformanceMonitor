# VAG Performance Monitor: оптимизация частоты опроса телеметрии

> Ниже — исходный текст задания на 0.6.0; добавлена только эта врезка.
> Что реализовано, что проверено и что осталось за оборудованием — в
> [отчёте](TELEMETRY_OPTIMIZATION_REPORT.md) и
> [заметках к релизу](releases/0.6.0.md). Целевые частоты не считаются
> достигнутыми до измерений на реальном адаптере.

## 1. Цель

Оптимизировать существующее диагностическое ядро VPM для быстрого и стабильного получения показателей через ELM327.

Основные задачи:
- Увеличить частоту обновления приоритетных показателей.
- Сократить количество таймаутов и бесполезных запросов.
- Исключить мерцание значений при единичных ошибках чтения.
- Реализовать контроль актуальности данных.
- Сохранить совместимость с Android, Android Auto, DashGrid и Android App Widgets.

Не изменять существующий дизайн и пользовательские сценарии.

## 2. Приоритеты опроса

Разделить параметры на три группы.

| Параметр | Приоритет | Целевая частота | Срок актуальности |
|---|---|---|---|
| Обороты двигателя | P0 | 10 Гц | 5 сек |
| Скорость автомобиля | P0 | 10 Гц | 5 сек |
| Давление наддува | P0 | 5–10 Гц | 5 сек |
| Температура масла | P0 | 1–2 Гц | 5 сек |
| Температура ОЖ | P0 | 1–2 Гц | 5 сек |
| Крутящий момент | P1 | 2–5 Гц | 5 сек |
| Мощность | P1 | 2–5 Гц | 5 сек |
| Текущая передача | P1 | 2–5 Гц | 5 сек |
| Положение педали акселератора | P1 | 2–5 Гц | 5 сек |
| Давление топлива | P1 | 1–2 Гц | 5 сек |
| Температура DSG | P2 | 0,5–1 Гц | 30 сек |
| Коррекции форсунок | P2 | 0,5–1 Гц | 30 сек |
| Показатели DPF | P2 | 0,2–0,5 Гц | 30 сек |
| Остальные диагностические параметры | P2 | 0,2–1 Гц | 30 сек |

Указанные частоты являются целевыми, а не гарантированными.

При недостаточной пропускной способности адаптера снижать частоту P2, затем P1. Параметры P0 должны иметь преимущество, при этом необходимо предотвращать бесконечное откладывание остальных запросов.

## 3. Планировщик запросов

Проанализировать существующую реализацию опроса и заменить неэффективные участки единым адаптивным планировщиком `TelemetryScheduler`.

Требования:

- Независимый интервал опроса каждого параметра.
- Приоритетная очередь запросов.
- Только одна активная транзакция с ELM327 одновременно.
- Отсутствие дублирующихся запросов.
- Группировка запросов по ECU для минимизации переключений адресов.
- Кеширование текущей конфигурации адаптера.
- Пакетное чтение нескольких DID, если оно поддерживается ECU и адаптером.
- Адаптивные интервалы опроса на основании фактической задержки ответов.
- Раздельная обработка таймаутов, отрицательных ответов UDS и ошибок транспорта.
- Ограничение повторных попыток чтения.
- Постепенное снижение частоты запросов к параметрам, которые систематически не отвечают.
- Периодическая повторная проверка недоступных параметров.

Не выполнять повторную инициализацию ELM327 или диагностической сессии перед каждым запросом без необходимости.

Сканирование блоков, чтение ошибок и идентификация ECU не должны выполняться параллельно с основным потоком запросов к адаптеру.

## 4. Приоритет источников данных

Для каждого показателя определить доступные источники:

- Стандартный OBD-II PID.
- Расширенный VAG UDS DID.
- Расчетный показатель на основании других параметров.

Выбирать наиболее быстрый и стабильный источник, соответствующий физическому смыслу показателя.

Не опрашивать одновременно несколько источников одного показателя без необходимости.

Проверить корректность определения давления наддува. Не путать абсолютное давление во впускном коллекторе с избыточным давлением наддува.

Для расчета избыточного давления использовать актуальное атмосферное давление, если оно доступно.

## 5. Хранение и актуальность данных

Для каждого параметра хранить:

- `parameterId`
- `value`
- `unit`
- `lastSuccessfulReadAt`
- `lastAttemptAt`
- `hasEverBeenRead`
- `consecutiveFailures`
- `priority`
- `pollIntervalMs`
- `staleTimeoutMs`
- `source`
- `status`

Использовать следующие состояния:

| Состояние | Условие | Отображение |
|---|---|---|
| `VALID` | Значение получено и актуально | Числовое значение |
| `STALE` | Последнее значение устарело | `—` |
| `NEVER_READ` | Значение ни разу не было успешно получено | `N/A` |

### Правила отображения

1. Если параметр успешно прочитан, отображать последнее полученное значение.
2. Если очередной запрос завершился ошибкой, сохранять последнее корректное значение до истечения срока актуальности.
3. Для параметров P0 и P1 отображать прочерк, если с момента последнего успешного чтения прошло более 5 секунд.
4. Для параметров P2 отображать прочерк, если с момента последнего успешного чтения прошло более 30 секунд.
5. Если параметр ни разу не был успешно прочитан в текущей диагностической сессии, отображать `N/A`.
6. После получения нового корректного значения немедленно восстановить числовое отображение.
7. Нулевое значение является допустимым результатом и не должно заменяться прочерком или `N/A`.
8. При потере соединения применять общие правила актуальности.

Не обновлять `lastSuccessfulReadAt` при ошибке, таймауте, некорректном ответе или повторной публикации кешированного значения.

Для расчета возраста данных использовать монотонное время Android (`SystemClock.elapsedRealtime()`).

Проверять актуальность независимо от поступления новых ответов, включая ситуацию полной потери соединения.

## 6. Единый источник данных

Все компоненты должны получать данные и их состояние из единого `TelemetryRepository`:

- Главный экран VPM.
- Полноэкранный дашборд.
- Android Auto.
- DashGrid.
- Android App Widgets.

Не создавать отдельные подключения к ELM327 для каждого потребителя.

Состояния `VALID`, `STALE` и `NEVER_READ` должны одинаково интерпретироваться всеми компонентами.

Частота обновления интерфейса не должна определять частоту диагностических запросов. Учитывать системные ограничения обновления Android App Widgets.

## 7. Диагностика производительности

Добавить сбор следующих технических метрик:

- Фактическая частота обновления каждого параметра.
- Средняя задержка ответа.
- P95 задержки ответа.
- Количество запросов в секунду.
- Процент успешных ответов.
- Количество таймаутов.
- Количество переключений ECU.
- Возраст последнего корректного значения.
- Количество переходов в состояние `STALE`.
- Текущая глубина очереди запросов.

Предусмотреть возможность экспорта диагностического журнала для последующего анализа работы на реальном автомобиле.

## 8. Тестирование

Добавить автоматические тесты следующих сценариев:

- Успешное получение параметра.
- Параметр никогда не был прочитан.
- Единичный таймаут без исчезновения значения.
- Устаревание частого параметра после 5 секунд.
- Устаревание редкого параметра после 30 секунд.
- Восстановление значения после серии ошибок.
- Корректное отображение нулевых значений.
- Полная потеря соединения.
- Медленный адаптер.
- Неподдерживаемый DID.
- Перегрузка очереди запросов.
- Одновременная подписка нескольких компонентов приложения.

## 9. Критерии приемки

- Приоритетные показатели обновляются с максимально доступной стабильной частотой.
- Редкие параметры не препятствуют получению приоритетных.
- Единичные ошибки чтения не вызывают появления прочерков.
- Устаревшие значения не отображаются как актуальные.
- Ни разу не полученные показатели отображаются как `N/A`.
- Отсутствуют конкурирующие подключения к адаптеру.
- Сохранена поддержка существующих диагностических профилей.
- Сохранен текущий дизайн всех экранов и виджетов.
- Не отправляются команды изменения кодировок, адаптаций или исполнительных механизмов ECU.

## 10. Порядок выполнения

Сначала изучить существующий код VPM и определить узкие места диагностического ядра.

Выполнить оптимизацию без необоснованного переписывания приложения и замены работающих компонентов.

При необходимости использовать архитектурные решения следующих проектов с учетом их лицензий:

- https://github.com/gdm0991/vagdiag
- https://github.com/bsdate-cc/universal-elm327-logger
- https://github.com/OBDb/Volkswagen-Golf
- https://github.com/bri3d/mcd-diag-rs

По завершении предоставить отчет об изменениях, результаты тестов и инструкцию по замеру производительности на реальном ELM327.

Не считать целевые частоты достигнутыми без фактических измерений.
