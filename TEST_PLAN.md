# План тестирования

## Автоматические тесты

```sh
./gradlew :app:testStandardDebugUnitTest
```

25 JVM-тестов, эмулятор и автомобиль не нужны. Те же тесты прогоняются
для варианта `aa`: `./gradlew :app:testAaDebugUnitTest`.

| Файл | Что проверяет |
|---|---|
| `ValueSpecTest` | декодирование 1/2 байт, знак, смещение, масштаб, little-endian, короткий ответ → null |
| `SignalCatalogTest` | уникальность ID, наличие PID и декодера, зависимости вычисляемых, целостность дашбордов, отсутствие преждевременного `CONFIRMED` |
| `ObdPayloadTest` | ответ с CAN-ID, без заголовка, склеенный, отрицательный, чужой PID, UDS DID |
| `TelemetryEngineTest` | опрос дашборда, приоритет над каталогом, вычисление наддува/момента/мощности, устаревание, backoff неподдерживаемого PID |
| `DemoSignalSourceTest` | согласованность модели, неизвестный сигнал, маркировка ДЕМО |

## Сборка

| Проверка | Команда | Критерий |
|---|---|---|
| Debug APK `standard` | `./gradlew :app:assembleStandardDebug` | `app/build/outputs/apk/standard/debug/app-standard-debug.apk` существует |
| Debug APK `aa` | `./gradlew :app:assembleAaDebug` | `app/build/outputs/apk/aa/debug/app-aa-debug.apk` существует |
| Установка рядом с VAG Diag | `adb install app-standard-debug.apk` | отдельная иконка, оба приложения сосуществуют |
| Запуск без GMS | устройство/эмулятор без Google Play Services | приложение стартует, ДЕМО работает |
| Один `applicationId` | установить `aa` поверх `standard` | вторая сборка заменяет первую, а не ставится рядом |

## Ручная проверка ДЕМО (без автомобиля)

1. Запустить приложение — открывается диагностический экран.
2. Нажать «Приборы» — открывается «Движение», бейдж **ДЕМО**.
3. Убедиться, что три колодца и пять плиток показывают меняющиеся числа,
   а не нули.
4. Переключиться на «Динамика» — наддув, мощность, момент согласованы:
   при росте оборотов растут мощность и наддув.
5. Открыть «Данные» — 45 записей, поиск по «масло» находит сигналы,
   фильтр «Топливо» оставляет только топливные.
6. Проверить, что непрочитанные сигналы показывают «—» и «не опрашивался»,
   а не 0.
7. Повернуть экран — разметка не ломается.
8. Закрыть приборку и открыть снова — счётчики продолжают обновляться.

## Ручная проверка с адаптером (после появления оборудования)

Предусловие: зажигание включено, двигатель заглушен (для безопасности).

1. Подключить Wi-Fi-адаптер, нажать «Подключиться».
2. Убедиться, что определились версия адаптера и напряжение.
3. Открыть «Приборы», нажать **ELM327** — бейдж меняется на зелёный,
   в шапке виден канал.
4. Сверить обороты, скорость, температуру ОЖ с приборкой автомобиля.
5. Проверить поддерживаемые PID: масло (0x5C), момент (0x61–0x63),
   давление в рампе (0x23). Неподдерживаемые должны дать «—».
6. Выдернуть адаптер — значения должны стать «—»/«устарело», приложение
   не должно падать.
7. Вставить адаптер обратно, переподключиться — телеметрия возобновляется
   без перезапуска.
8. Запустить поиск блоков и одновременно открыть приборку — убедиться,
   что команды не переплетаются и приложение остаётся работоспособным
   (ожидаемо: оба процесса замедляются).
9. Повторить для Bluetooth и USB, если есть адаптеры.

Результаты записывать в [`COMPATIBILITY.md`](COMPATIBILITY.md), а не в
переписку: иначе они теряются.

## Тестирование через эмулятор адаптера

`Ircama/ELM327-emulator` в этой итерации не подключён. План:

- поднять эмулятор с ответами на 01 0C, 01 0D, 01 05, 01 42;
- добавить сценарии «NO DATA», обрыв на первом кадре, мусор в буфере;
- прогнать `Elm327SignalSource` против эмулятора, а не только против
  поддельного источника.

Эмуляция не заменяет проверку на автомобиле и не даёт статус `CONFIRMED`.

## Ручная проверка настроек и профиля

1. Открыть настройки из шапки приборки или с диагностического экрана.
2. Выбрать Wi-Fi, Bluetooth или USB; проверить, что список устройств
   заполняется и «Подключиться» меняет статус.
3. Сохранить профиль Golf 7.5, выбрать и снять несколько параметров,
   сохранить и перезапустить приложение — набор должен сохраниться.
4. Проверить «Демо» и «Отключить»: статус, бейдж и значения меняются.
5. Включить автоподключение, перезапустить приложение с подключённым
   адаптером — соединение должно подняться без ручных действий.

## Ручная проверка виджета

1. Добавить виджет «Телеметрия AA» на рабочий стол.
2. Открыть конфигуратор, выбрать заголовок и до четырёх параметров.
3. Убедиться, что значения обновляются, а «—» показывается вместо нуля.
4. Добавить второй экземпляр с другим набором — настройки не должны
   пересекаться.
5. Нажать на виджет — должна открыться приборка.
6. Уменьшить виджет до компактного размера — должны остаться два параметра.

## Ручная проверка Android Auto

Предусловие: установлена сборка `aa`, доступен Desktop Head Unit или
головное устройство с поддержкой Car App Library.

1. Запустить DHU и подключить телефон.
2. Найти «AA Performance» в списке приложений хоста.
3. Проверить строку состояния и до восьми параметров профиля.
4. Переключить ДЕМО/ELM327 в телефоне — список должен обновиться.
5. Проверить, что без профиля показывается сообщение «Нет доступных
   параметров», а не падение.

## Фоновая служба

1. Подключить адаптер или оставить ДЕМО, свернуть приложение.
2. Убедиться, что в шторке есть постоянное уведомление с кнопкой
   «Отключить».
3. Проверить обновление виджета при свёрнутой Activity.
4. Нажать «Отключить» в уведомлении — служба и соединение должны
   остановиться, виджет перейти в «—».
5. Убить процесс из настроек Android — после запуска приложение должно
   восстановить кэш и, при автоподключении, соединение.

- [ ] Виджет на лаунчере.

- Реальный ELM327, реальный Golf 7.5, Bluetooth/USB-адаптеры.
- Головное устройство Android Auto, Desktop Head Unit, AARE/DashGrid.
- Частота обновления виджета на реальном хосте и при выключенном экране.
- Поведение EMUI 14+.
