# Безопасность

## Границы записи

Новый интерфейс телеметрии — только чтение. Он не содержит кодирования,
адаптаций, записи в ECU, актуаторов, сброса блоков, обхода SFD/Security
Access и управления регенерацией DPF.

Диагностический экран унаследован от VAG Diag. В нём остаётся ручное
стирание кодов ошибок (UDS 0x14 и OBD mode 04) — единственная операция
записи. Она:

- выполняется только по явному нажатию пользователя;
- никогда не запускается автоматически;
- сбрасывает готовность систем самодиагностики, поэтому после неё нужен
  пробег для техосмотра.

Если приложение должно быть строго read-only, эту кнопку нужно убрать в
следующей итерации. Решение вынесено в [`BACKLOG.md`](BACKLOG.md), а не
спрятано.

## Разрешения

| Разрешение | Зачем |
|---|---|
| `INTERNET`, `ACCESS_NETWORK_STATE` | TCP-соединение с Wi-Fi-адаптером в локальной сети |
| `BLUETOOTH`, `BLUETOOTH_ADMIN` (до Android 12) | поиск и подключение SPP-адаптера |
| `BLUETOOTH_CONNECT`, `BLUETOOTH_SCAN` (Android 12+) | то же на новых версиях |
| USB host (feature) | адаптер через OTG; не требуется для установки |

Приложение не запрашивает местоположение, камеру, контакты, хранилище
общих файлов и не пользуется фоновой геолокацией.

## Сеть

Единственное сетевое соединение — TCP-сокет к адаптеру по адресу, который
ввёл пользователь (по умолчанию `192.168.0.10:35000`). Никакой телеметрии,
аналитики, crash-репортов и обращений к сторонним API нет.

Проверка зависимостей:

- `androidx.*` — Apache 2.0, без сетевой активности;
- `usb-serial-for-android` (JitPack) — MIT, локальная работа с USB;
- Firebase, GMS, Crashlytics, Facebook SDK и рекламные сети отсутствуют.

JitPack — внешний источник сборки. Это риск цепочки поставок: для
воспроизводимой сборки версию библиотеки нужно фиксировать, а артефакт —
сверять по хешу. Задача вынесена в бэклог.

## Данные

Всё хранится локально. Записи поездок пока нет; когда появится, она также
будет локальной, с явным экспортом по действию пользователя.

## Отказы и ограничения

- Во время диагностики адаптер и блоки могут отвечать медленно или
  обрывать длинные ответы. Приложение показывает «—», а не выдуманное
  значение.
- Приборка и диагностический экран используют одно соединение. Команды
  сериализованы, но одновременное сканирование блоков и опрос телеметрии
  замедляет оба процесса. Не запускайте тяжёлое сканирование в движении.
- Не пользуйтесь приложением за рулём. Диагностика выполняется на
  стоящем автомобиле с включённым зажиганием.
- ДЕМО-режим — модель, а не данные автомобиля. Он не подтверждает
  совместимость.

## Отчёт об уязвимости

Это учебно-тестовый проект без серверной части. При обнаружении проблемы
создайте issue в репозитории, не прикладывая VIN, номера блоков и
персональные данные.
