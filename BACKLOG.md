# Бэклог

Приоритеты: **P0** — без этого нельзя считать текущую итерацию проверенной;
**P1** — следующий содержательный шаг; **P2** — расширение.

## P0

| Задача | Зачем |
|---|---|
| Проверить приложение на реальном автомобиле VAG | все сигналы сейчас `DECODED`, ни один не `CONFIRMED`; без машины это не исправить |
| Сверить поддерживаемые PID с целевым блоком двигателя | 0x5C, 0x61–0x63, 0x23 могут отсутствовать |
| Запустить приборку и настройки на реальном смартфоне | Compose-вёрстка не запускалась на устройстве |
| Проверить виджет на лаунчере | настройка экземпляров, обновление, переход в приборку |
| Проверить Android Auto через DHU | сборка `aa` компилируется, но хост не проверялся |
| Проверить Bluetooth и USB на живых адаптерах | в базовом проекте они не проверены |
| Проверить foreground-службу и уведомление | поведение при сворачивании, отключении и убийстве процесса |
| Автопереподключение после обрыва | сейчас автоподключение работает только при старте приложения |
| Решить судьбу ручного стирания ошибок | ТЗ требует read-only; в унаследованном экране кнопка есть |
| Подключить ELM327-emulator к тестам | проверить разбор реальных ответов, а не только поддельного источника |
| Зафиксировать версию `usb-serial-for-android` и хеш | JitPack — риск цепочки поставок |

## P1

| Задача | Зачем |
|---|---|
| Определение автомобиля по VIN | профили уже ручные, но каталог не подстраивается сам |
| Подтвердить VAG DID на живом MQB TDI | 83 сигнала декодированы, но ни один не CONFIRMED |
| Haldex и AdBlue через UDS | в открытом наборе их нет или нужна сессия `10 03` |
| Импорт OBDb (JSON) с проверкой лицензий | расширение каталога без выдумывания |
| Запись поездок и экспорт CSV/JSON | требование ТЗ, полезно для отладки сигналов |
| Конструктор дашбордов | главная продуктовая функция после телеметрии |
| Настройка единиц и точности | бар/кПа, л/100 км, °C/°F |
| Экран Vehicle Health | температуры, коррекции, DSG, Haldex, ошибки |
| Решить судьбу `allowBackup` | профиль, VIN и кэш значений не должны уходить в облачный бэкап незаметно |
| Проверить энергопотребление службы | постоянный опрос OBD и виджет не должны съедать батарею |

## P2

| Задача | Зачем |
|---|---|
| AARE / автомобильный экран | проекция на головное устройство |
| Публикация Android Auto в Google Play | нужен белый список хостов и проверка категории |
| Импорт ODX/PDX и ASAM-MCD | глубокие параметры блоков |
| MQB Evo, MLB, MEB | расширение платформ |
| KWP2000 и TP2.0 | автомобили до 2010 года |
| CAN FD и DoIP | отдельные транспорты, не через ELM327 |
| Сравнение поездок и графики | после записи |
| Локализация на английский | RU — основной язык проекта |

## Технический долг

- Один Gradle-модуль: разделение на `core`/`features` отложено до второго
  потребителя телеметрии.
- Диагностика и телеметрия делят адаптер через `AdapterBus`, но у
  диагностики нет собственных приоритетов: во время скана опрос телеметрии
  просто ждёт. Если понадобится, скан можно разбить на шаги с паузами
  для P0-параметров.
- Дублирование форматирования значений между приборкой, Live Data и виджетом.
- Нет скриншот-тестов Compose.
- `README` базового проекта описывает функции, которых в этом форке может
  не быть; документацию нужно синхронизировать по мере изменений.
